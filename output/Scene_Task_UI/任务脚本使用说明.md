# Scene_Task 任务脚本使用说明

本次已将工程脚本编辑器中的旧“★任务系统”替换为 `Scene_Task`，移除此前叠加的“主线任务日志”，并修改环形菜单的任务入口。可编辑源码另存于 `Scripts/Scene_Task.rb`。该文件不会被游戏自动加载；实际运行的是 `Data/Scripts.rxdata` 中的同名脚本。后续请在脚本编辑器中编辑同名脚本，或将修改后的源码全文替换进去。

接受任务和根据进度更新任务的方式参照你提供的 `task.txt`（叶子《详尽任务显示界面 v2.1》）。界面、分类、记录和存档迁移为本项目重新实现。

## 当前行为

- 三个分类：主线 `○`、支线 `△`、特殊任务 `☆`；完成后分别显示 `●`、`▲`、`★`。
- 只有事件调用 `get_task(任务编号)` 才接受任务。修改变量不会自动接受尚未获得的任务。
- 已接受任务的目标、完成状态、过期状态和线路显示条件，随所配置的变量、开关更新。
- 本批主线共35条：变量15从5至175，每5点变动一次；5～9时任务1的目标和说明完全一致，10时任务1完成并接受任务2。180完成本批最后一条任务，没有添加后续剧情。
- 已完成任务保留在列表后方；右侧显示完成报告。区间内的数值不改变任务文字、状态，也不触发任务更新提示。
- 地图上短暂显示接受、目标更新或完成提示。对话、剧情演出和地图名称显示期间暂缓；同一段演出连续更新会合并提示，完整记录仍在日志中。
- 新支线和特殊任务的剧情尚未编写；旧存档里已经获得的旧支线会保留。
- 老存档第一次进入地图时，根据每条任务自己的迁移条件合并记录，无须修改原存档文件。重新存档后保存新的任务记录。

本批剧情节点已经补入 `get_task`，不必再手动重复添加。后续新任务需要在对应事件里添加接受指令。

## 事件指令

```ruby
get_task(1)                   # 接受任务1；重复接受不产生重复记录
finish_task(1)                # 手动完成任务1，并保留记录
remove_task(1)                # 从记录中移除任务1
$scene = Scene_Task.new       # 直接打开任务界面
```

`get_task` 的数字是任务资料的编号，不是变量编号。任务1对应变量15进度5，任务2对应进度10。变量驱动完成的任务通常无须调用 `finish_task`；变量达到条件即可完成。任务系统不自动发放经验、金钱或物品，奖励仍由剧情事件负责。

调试指令 `get_all_task` 接受所有已定义任务，`finish_all_task` 完成所有已获得任务。它们不适合放在正常剧情中。

## 添加第二、三章AB线

主线、支线和特殊事件统一写在 `Game_Party#get_tasks_info` 中，每条单独成块，只有分类字段不同。新增定义放在现有条目之后、旧存档兼容段之前。不同任务使用不同编号。变量和开关由你按实际剧情选择，下面的16、17、61、62仅为示例，不代表已改变工程线路。

```ruby
# A线：变量16负责进度，开关61表示进入A线。
briefing = "前往指定地点，与角色交谈。"
completed = $game_variables[16] >= 10
briefing = "完成报告：已经确认线索的去向。" if completed
@tasks_info[101] = Game_Task.new(
  "调查新的线索", briefing, nil, :main, completed,
  "第二章 A线", [16], [61], "$game_switches[61]")

# B线可以使用完全独立的变量、开关和任务编号。
@tasks_info[102] = Game_Task.new(
  "寻找另一条道路", "前往指定地点调查。", nil, :main,
  $game_variables[17] >= 10, "第二章 B线",
  [17], [62], "$game_switches[62]")
```

进入A线的事件先设置开关61，再设置变量16的起始进度，随后调用 `get_task(101)`；B线对应调用 `get_task(102)`。未选择线路的任务不会显示，隐藏不会删除已经获得的记录。第三章继续增加独立编号、进度变量和线路条件即可，不需要修改核心系统。

`Game_Task.new` 的参数按顺序为：标题、简介、过期条件、分类、是否完成、章节名、依赖变量编号数组、依赖开关编号数组、显示条件。分类使用 `:main`、`:side`、`:special`。依赖数组要列出简介、完成、过期和显示条件所使用的所有变量、开关，保证修改后立即更新。`nil` 过期条件表示永不过期；过期条件可以写成 `"$game_switches[53]"`，并将53列入依赖开关数组。完成任务不会再显示为过期。

如需让新增任务支持旧存档补录，可另设：

```ruby
@tasks_info[101].migration = [16, 5]
```

此条件表示旧任务系统存档在变量16达到5且符合线路显示条件时补入任务101；它不用于新游戏自动接受任务，也不会反复补入已迁移存档。

## 本批主线编号

没有单独的主线资料表。`get_tasks_info` 中每条任务按以下写法定义；将 `category` 改成 `:side` 或 `:special`，即可写支线或特殊事件：

```ruby
id          = 1          # 任务编号：事件调用 get_task(1)
category    = :main      # :main 主线 / :side 支线 / :special 特殊
chapter     = "序章"     # 所属章节
name        = "突来的通缉" # 任务标题
description = "一张拘捕令打乱了采蘑菇的计划。" # 剧情说明
objective   = "应对堵在魔法店门口的红魔警察。" # 当前目标
report      = "击退了红魔警察，决定去香霖堂打听消息。" # 完成报告
completed   = $game_variables[15] >= 10 # 变量完成条件
completed ||= (@task_manual_completed || {})[id] == true # 支持手动完成

briefing = "\\c[9]剧情说明\\c[0]\n#{description}\n\n"
if completed
  briefing += "\\c[6]完成报告\\c[0]\n#{report}"
else
  briefing += "\\c[6]当前目标\\c[0]\n#{objective}"
end

@tasks_info[id] = Game_Task.new(
  name, briefing, nil, category, completed, chapter, [15])
@tasks_info[id].migration = [15, 5] # 旧存档补录条件
```

一条任务只有一份剧情说明和一个当前目标，没有嵌套的小阶段列表。本批恢复原有1～35编号，与已经补入事件中的 `get_task` 指令一致。5～9期间完全不变；10时完成任务1并接受任务2，依此类推。

## 界面与操作

底图为 `Graphics/Windowskins/Scene_Task_v2.png`，参照你提供的深色银金纹样生成，游戏内按640×480显示。

左右键切换分类，上下键选择任务，确认键进入正文阅读模式，上下键滚动；取消键返回列表或退出界面。L/R键分别翻列表页或正文页。由环形菜单进入时返回环形菜单，由剧情事件直接打开时返回地图。

正文支持参考脚本的 `\\v[n]`、`\\n[n]`、`\\c[n]`、`\\i[文件名]` 和 `\\p[文件名]`。在Ruby双引号字符串中要写两条反斜线。
